팩이란

팩은 코드가 없는 데이터 묶음이에요. 엑스퍼트 서버가 켤 때 읽어서 게임에 얹어요. 코드를 넣을 수 없으니 서버도 안전하고, 같은 팩이면 어디서나 같은 결과가 나와요(대전·다시 보기가 어긋나지 않아요).

플러그인 plugin캐릭터·재료·무기·규칙 (게임 내용). .json 하나로 돼요.
리소스 resource색·로고·배경·캐릭터 그림·효과음·음악. 그림·소리 파일과 함께 .zip.
종합 bundle둘 다. .zip.
  • 엑스퍼트 서버에서만 읽어요. 바닐라 서버는 plugins/ 폴더를 무시해요.
  • 게임 내용을 바꾸면 그 서버의 규칙 이름(ruleset)이 custom-해시가 돼요. 리소스만 바꾸면 official 그대로예요.
  • 능력은 이미 있는 능력 중에서 골라요(새 능력 코드는 못 넣어요). 무기는 숫자 배율만 줄 수 있어요.
  • 팩이 틀리면 팩 전체를 거절해요(일부만 적용하지 않아요). 이유는 서버 기록과 이 위키의 검사기에 나와요.

빠른 시작

  1. 예시 팩 받기: example-pack.json (플러그인), night-skin (리소스), starfall (종합)
  2. 고치기: id 를 내 팩 이름(영소문자·숫자·-)으로 바꾸고 내용을 바꿔요.
  3. 검사하기: 아래 팩 검사기에 붙여 넣거나 파일(.json/.zip)을 골라요.
  4. 서버에 넣기: 엑스퍼트 서버의 plugins/ 에 넣고 서버를 다시 켜요 (서버별 방법).
  5. 확인: 로비의 이 서버의 팩 단추와 가이드의 팩 탭에 나와요. 새 캐릭터는 도감·상점에 바로 나와요.

{
  "apiVersion": 1,
  "id": "my-first",
  "name": "첫 팩",
  "version": "1.0.0",
  "rules": { "rerollCost": 1 }   // 새로고침 1골드
}

PC 에서 바로 시험해 보려면 엑스퍼트 로컬 서버(commander-server-expert-…)를 받아 켜고, 옆의 commander-data/plugins/ 에 넣으면 돼요.

pack.json 기본

맨 위에 올 수 있는 이름은 아래뿐이에요. 다른 이름이 있으면 거절해요(오타를 잡기 위해서예요).

이름필수내용
apiVersion필수팩 형식 버전. 지금은 1
id필수팩 이름표. 영소문자로 시작, 영소문자·숫자·- 2~31자. 다른 팩과 겹치면 안 돼요. 팩 안의 캐릭터·재료·무기는 팩id:이름 으로 불려요.
name필수보여 줄 이름
version필수팩 버전 글 (예: 1.0.0)
kindplugin | resource | bundle. 안 쓰면 내용을 보고 정해요 (리소스만 → resource, 둘 다 → bundle, 나머지 → plugin). 리소스 팩에 게임 내용, 플러그인 팩에 resources 가 있으면 거절.
description한두 줄 설명 (로비 팩 목록)
author만든 사람
guide가이드 "팩" 탭에 나올 설명서 → 팩 설명서
units새 캐릭터 → 새 캐릭터
unitOverrides공식(또는 앞선 팩) 캐릭터 조정 → 조정
materials, weapons, fusions재료·무기·조합 → 재료·무기
rules규칙 값 → 규칙
resources화면·소리 → 리소스 (리소스·종합 팩만)

여러 팩은 id 순서로 차례대로 얹어요. 뒤의 팩은 앞의 팩이 만든 캐릭터를 unitOverrides 로 조정할 수 있어요.

새 캐릭터 units 팩마다 40명

{
  "id": "moon-guard",        // 팩 안의 이름 → 게임에서는 "팩id:moon-guard"
  "nameKo": "달빛 수호병",     // 24자까지
  "piece": "rook",             // king · queen · rook · bishop · knight · pawn
  "faction": "달",             // 계열 이름표 (이야기용, 규칙에는 안 씀) 16자까지
  "cost": 2,                    // 1~4 골드
  "role": "탱커",              // 역할 (아래 표)
  "ability": "shield-wall",    // 능력 목록 중 하나
  "abilityText": "자신과 인접 아군에게 보호막",  // 80자까지
  "hpMult": 1.1, "atkMult": 1.0,  // 선택: 배율 0.3~3
  "lite": true                   // 선택: 체험판(연습 대전)에도 나옴
}

능력치 계산

능력치는 공식 캐릭터와 같은 공식으로 계산하고 배율만 곱해요. 숫자를 직접 줄 수는 없어요(밸런스를 지키려고요).

체력 = 가격 기본 체력 × 역할 체력 × 기물 체력 × hpMult (5 단위로 반올림)
공격 = 가격 기본 공격 × 역할 공격 × 2.5 × 기물 공격 × atkMult

값을 고르면 능력치가 나와요.

제한

  • 한 팩에 40명, 모든 팩을 합쳐 캐릭터 120명까지.
  • 가격마다 상점에 나올 캐릭터가 한 명 이상 있어야 해요.
  • 캐릭터의 별 등급(★2, ★3), 상점 확률, 진화는 공식과 같은 규칙을 따라요.

능력 목록

ability 에 쓸 수 있는 이름이에요. 같은 능력을 쓰는 공식 캐릭터의 설명을 같이 보여 줘요. 패시브는 에너지가 아니라 조건(쓰러질 때 등)으로 발동해요.

재료·무기·조합

재료를 재련하면 무기가 나와요. 그래서 새 재료와 새 무기는 서로를 가리켜야 하고 희귀도도 같아야 해요.

{
  "materials": [ { "id": "moonstone", "nameKo": "달돌", "rarity": "common", "weapon": "moon-bow" } ],
  "weapons": [ { "id": "moon-bow", "nameKo": "달돌 활", "material": "moonstone", "rarity": "common",
                  "text": "공격 +20%, 에너지 충전 +20%", "stats": { "atk": 1.2, "energy": 1.2 } } ],
  "fusions": [ { "a": "moonstone", "b": "clawstone", "result": "titanium" } ]
}
  • 희귀도: common → uncommon → rare → legendary
  • 무기 stats (배율, 1 이 기본, 하나 이상): atk 0.5~2, hp 0.5~2, dmgTaken 0.5~1.5, energy 0.5~2. text 는 보여 줄 설명(100자)이에요. 확률 효과(출혈 등)는 코드라서 팩이 만들 수 없어요.
  • 조합 fusions: 같은 희귀도의 서로 다른 재료 둘 → 한 단계 위 재료. 이 팩의 재료는 짧은 id, 공식·다른 팩 재료는 전체 id 로 써요. 안 정한 짝은 서버가 알아서 채워요.
  • 제한: 모든 팩을 합쳐 재료 40개, 무기 60개.

리소스 resources 리소스·종합 팩

경로는 모두 pack.json 이 있는 폴더 기준이에요 (예: assets/logo.png). 웹과 안드로이드 앱이 바로 적용해요. iPad 앱은 아직 목록과 설명서만 보여 줘요.

    "sounds": { "buy": "sfx/buy.wav" },

{
  "guide": [
    { "title": "혜성 기사", "body": "새 3골드 나이트예요.\n· 도약해서 뒷줄을 노려요" },
    { "title": "바뀐 규칙", "body": "새로고침이 1골드예요." }

  • 12칸까지. title 40자, body 4000자까지. 그냥 글자예요(HTML 은 안 돼요). 줄바꿈은 \n.
  • 안 써도 가이드의 "팩" 탭에는 자동 요약(새 캐릭터, 바뀐 캐릭터, 재료, 무기, 규칙, 화면·소리)이 나와요.

zip 과 서버에 넣기

그림·소리가 있으면 pack.json 과 파일을 zip 하나로 묶어요. pack.json 이 맨 위에 있어도, 폴더째 압축해도 돼요(pack.json 이 있는 폴더를 기준으로 봐요). 맥의 __MACOSX 같은 숨김 파일은 무시해요.

night-skin.zip
├─ pack.json
├─ assets/logo.png
├─ assets/units/relic.jpg
└─ sfx/buy.wav
# 터미널에서
cd night-skin && zip -r ../night-skin.zip .

zip 하나를 풀면 40MB, 파일 600개까지예요.

서버넣는 곳
로컬 서버 (PC, 엑스퍼트)실행파일 옆 commander-data/plugins/ 에 이름.json, 이름.zip, 폴더/pack.json. zip 은 켤 때 풀려요. 끄려면 이름 끝에 .off. 서버를 다시 켜면 적용.
안드로이드 서버 앱플러그인 칸 → 팩 추가 에서 .json·.zip 고르기. 켜기/끄기·삭제도 거기서. 엑스퍼트로 다시 켜면 적용.
iPhone·iPad 서버 앱파일 앱 → 이 앱 → commander-data/plugins/ 에 .json, 또는 zip 을 풀어 폴더 이름을 팩 id 로 바꿔 넣기.
개발 서버 (Cloudflare)server/packs/ 에 넣고 server/packs/index.ts 에 등록, 배포. 그림·소리는 내보내지 않아요.

팩 검사기

서버가 켤 때와 같은 규칙으로 검사해요 (이 서버에 적용하지는 않아요). zip 을 고르면 pack.json 이 가리키는 그림·소리 파일이 zip 안에 있는지도 봐요.

자주 나는 오류

메시지고치는 법
알 수 없는 이름 …오타예요. 위의 표에 있는 이름만 쓸 수 있어요 (대소문자도 맞춰요).
apiVersion: 1 이어야 한다맨 위에 "apiVersion": 1 을 넣어요.
units[0].ability: … 중 하나여야 한다능력 목록의 이름을 그대로 써요.
units[0].cost: 1~4가격은 1~4 골드예요.
재련하면 나오는 무기 … 이(가) 없다재료의 weapon 과 무기의 id, 무기의 material 과 재료의 id 를 서로 맞춰요. 희귀도도 같게.
리소스 팩에는 게임 내용을 넣을 수 없다kind 를 bundle 로 바꾸거나 게임 내용을 빼요.
팩 안의 파일 경로여야 한다영문·숫자·_-./ 만, 상대 경로로. 한글·빈칸이 든 파일 이름은 바꿔요.
같은 id 의 팩이 둘이다서버의 plugins 폴더에 같은 팩이 두 번(예: .json 과 .zip) 들어 있어요.
(서버가 팩을 안 읽어요)바닐라 서버예요. 엑스퍼트 서버로 켜요. 또는 이름 끝이 .off·.sample 이에요.

버전과 호환

  • apiVersion 은 형식이 호환되지 않게 바뀔 때만 올라가요. 지금 서버가 아는 버전은 1 이에요.
  • 팩을 바꾸면 그 서버의 규칙 이름(ruleset)이 바뀌고, 진행 중이던 방은 버려져요(규칙이 도중에 달라지는 일이 없어요).
  • 캐릭터 id 는 전적·다시 보기에 남으니까, 한 번 내보낸 팩에서는 id 를 바꾸지 않는 게 좋아요. 이름(nameKo)은 바꿔도 돼요.
  • 앱과 웹은 접속한 서버의 목록을 읽으니까, 새 캐릭터가 따로 업데이트 없이 도감·상점에 나와요.
