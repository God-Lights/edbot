# COMMANDER 체스판 자동 전투 설계 (확정안 v1)

롤토체스처럼 상점에서 캐릭터를 사서 판에 놓고 자동 전투를 지켜보는 1대1 게임. 기물이 **체스 규칙**으로 움직이고 공격한다.
이 문서가 기준이다. 바꾸면 이 문서를 먼저 고친다. (옛 레인 타워 게임은 코드만 남겨 두고 화면에서 숨긴다.)

## 1. 한 줄 요약
"5개씩 나오는 상점에서 캐릭터를 사 체스판에 놓으면, 기물들이 체스 규칙으로 알아서 싸운다. 먼저 상대 체력을 0으로 만들면 승리."

## 2. 줄인 것 (1차 버전에서 뺐다)
| 뺀 것 | 이유 | 언제 다시? |
|---|---|---|
| 계열(세력) 시너지 축 | 시너지 축이 둘이면 배울 게 두 배 | 기물 시너지가 이해된 뒤 |
| ★3 | 복사본이 적은 1대1 풀에서는 거의 안 나옴 | 풀을 키울 때 |
| 연승·연패 보너스 | 계산이 늘어남 | 필요하면 |
| 경험치(레벨) | 라운드에 따라 올릴 수 있는 기물 수가 늘어나게 대체 | - |
| 탐사 4×4 지도와 매복 | 자원 칸이 대체 | 버림 |
| 이동 드랍, 재료 합성, 무기 ★2 강화, 상성 | 자원 시스템을 단순하게 | 자원 시스템이 이해된 뒤 |
| 레인, 타워, 점수, 스팀포스 | 새 게임에 없음 | 옛 모드로 보존 |

## 3. 한 판의 구조
- 라운드마다 **준비 25초(첫 라운드 40초) → 전투 최대 30초 → 결과 5초**. 최대 8라운드, 한 판 약 7분.
- 체력 30. 라운드에서 지면 `상대의 살아남은 기물 수 × 2 + 라운드 번호`만큼 잃는다. 0이 되면 패배. 8라운드가 끝나도 안 끝나면 체력이 높은 쪽 승리(같으면 마지막 라운드 승자).
- 항복은 언제든 가능(서버 구현됨). 연결이 30초 넘게 끊기면 기권패.

## 4. 판과 배치
- **8×8 체스판**, 위에서 내려다본 2D. 내 기물은 내 쪽 4줄 안에만 놓는다. 내 쪽이 항상 아래.
- 대기석 6칸. **판에 올릴 수 있는 기물 수**: 1라운드 3, 이후 라운드마다 +1, 최대 7.
- 준비 단계에서 상대 판은 보이지 않는다.

## 5. 전투 규칙 (체스 규칙)
전투는 **1초 한 박자**로 진행하는 결정적 시뮬레이션(같은 입력 → 같은 결과). 박자마다 모든 기물이 동시에 한 번 행동한다.

| 기물 | 이동 | 공격 (닿는 곳) |
|---|---|---|
| 킹 | 8방향 1칸 | 인접 8칸 |
| 퀸 | 직선·대각선 (최대 3칸) | 직선·대각선 (막히지 않은 곳, 최대 4칸) |
| 룩 | 직선 (최대 3칸) | 직선 (최대 4칸) |
| 비숍 | 대각선 (최대 3칸) | 대각선 (최대 4칸) |
| 나이트 | L자 점프(막혀도 넘음) | L자 위치 |
| 폰 | 앞으로 1칸 (항상 전진) | 앞쪽 대각선 인접 + 바로 앞 |

- 행동 순서: 공격할 수 있는 적이 있으면 **공격**(가장 체력이 낮은 적, 같으면 가장 가까운 적), 없으면 **가장 가까운 적 쪽으로 이동**.
- 공격은 "잡는다"가 아니라 **피해**를 준다(체력이 있다). 슬라이딩 기물(퀸, 룩, 비숍)은 중간에 기물이 있으면 그 너머를 못 친다.
- **에너지**: 공격하거나 맞을 때 차고, 가득 차면 능력이 **자동 발동**한다.
- **폰 승급**: 폰이 상대 쪽 끝줄에 닿으면 그 전투 동안 퀸으로 승급한다.
- **돌발 사망(sudden death)**: 20초가 지나면 모든 기물이 박자마다 점점 커지는 추가 피해를 받아 반드시 끝난다.
- **한 박자는 세 단계**로 진행하며 모든 기물이 박자 시작 때의 판을 보고 동시에 행동한다: ① 에너지가 찬 기물이 능력 발동 → ② 나머지는 공격하거나 이동할 칸을 정함 → ③ 이동. 같은 칸으로 가려 하면 체력이 많은 쪽이 가고, 같으면 이번 박자에 먼저 움직이는 쪽(박자가 짝수면 seat 0)이 간다. 같은 박자에 누가 비운 칸으로는 갈 수 없다.
- 이동할 칸은 "가장 가까운 적과의 거리가 줄어드는 칸"이고, 줄어드는 칸이 없으면 제자리다. **폰은 길이 열려 있으면 언제나 앞으로 나아간다**(승급하려고).
- 같은 조건에서 대상을 고를 때는 **내 시점의 좌표**(내 쪽이 항상 아래)로 순서를 정해서, 두 팀의 자리를 바꿔도 선택이 거울처럼 같다.

## 6. 상점과 경제
- 준비 단계마다 **상점 5칸**. 새로고침 2골드. 같은 캐릭터 **3장 = ★2**(체력·공격 약 1.8배, 능력 강화).
- 골드: 라운드 시작 5 + 이자(보유 골드 10마다 1, 최대 +3). 시작 골드 5. 팔면 산 값(★2는 3장 값)을 돌려받는다.
- **공용 풀**: 가격별 복사본 수(1골드 9장, 2골드 8장, 3골드 6장, 4골드 5장)를 둘이 나눠 쓴다. 산 캐릭터는 풀에서 줄어든다. 판 때 풀로 돌아간다.
- 상점 등급 확률은 라운드가 갈수록 비싼 캐릭터가 늘어난다(1~2라운드 1~2골드 위주, 6라운드부터 3~4골드 포함).

## 8. 시너지 (기물 축만)
같은 기물이 모이면 팀 전체 보너스. 킹·퀸·룩·비숍·나이트는 2명/3명, 폰은 2명/4명. (3명/4명은 효과가 약 1.5배) 수치는 초안.

| 기물 | 2명 효과 |
|---|---|
| 킹 | 아군 전체 에너지 충전 +20% |
| 퀸 | 능력 피해 +15% |
| 룩 | 받는 피해 -10% |
| 비숍 | 회복·보호막 +25% |
| 나이트 | 첫 도약 후 5초간 공격 +20% |
| 폰 | 폰 전체 공격 +15% (4명: 체력 +25% 추가) |

## 9. 자원 시스템 (2차 버전)
1~3단계가 재밌다고 확인된 뒤에 한꺼번에 얹는다. 1차 버전에는 없다.
- **자원 칸**: 라운드마다 판 중앙 근처에 4개(내 쪽·상대 쪽 거울 배치). 준비 단계에서 미리 보인다. 기물이 도착하면 채굴, 칸은 사라진다. 같은 박자에 둘이 도착하면 둘 다 얻는다.
- 재료 13종(희귀도: 흔함 60%, 보통 30%, 희귀 10%, 전설 칸에서 3%). 광물 시장: 라운드마다 1~2종, 한 라운드에 한 개, 흔함 3·보통 5·희귀 8골드.
- **재련대 2칸**: 재료 → 다음 라운드 시작에 같은 이름의 **무기**. 무기는 기물당 하나.

| 희귀도 | 재료 → 무기 | 효과 |
|---|---|---|
| 흔함 | 클로우스톤 → 클로우스톤 도끼 | 공격 +15%, 20% 확률 3초 출혈 |
| 흔함 | 에드뮴 → 에드뮴 블레이드 | 공격 속도 +20% |
| 흔함 | 비트 → 비트 대거 | 에너지 충전 +25% |
| 흔함 | 에드코인 → 에드코인 슬링 | 공격 +5%, 처치마다 골드 +1(라운드당 최대 3) |
| 보통 | 타이타늄 금속 → 타이타늄 방패 | 체력 +15%, 받는 피해 -10% |
| 보통 | 레드오션 → 레드오션 삼지창 | 공격이 인접 적 1명에게 40% 번짐 |
| 보통 | 에드잼 → 에드잼 보주 | 능력 효과 +25% |
| 보통 | 고대의 파편 → 고대의 파편 지팡이 | 전투 시작 시 최대 체력 25% 보호막(5초) |
| 희귀 | 안키오의 날개 → 안키오의 날개 쌍검 | 회피 20%, 공격 속도 +10% |
| 희귀 | 어둠의 정수 → 어둠의 낫 | 준 피해의 25% 흡혈 |
| 희귀 | 혼돈의 결정체 → 혼돈의 지팡이 | 공격 시 15% 확률 무작위 약화(기절 1초/둔화 3초/방어 감소 3초) |
| 전설 | 비트코인 → 비트코인 대검 | 공격 +30%, 살아남으면 라운드 종료 골드 +2 |
| 전설 | 디지털 채굴기 → 디지털 채굴기 포대 | 공격 +12%, 매 라운드 시작 때 비트 1개 생성 |

## 10. 밸런스 목표 (봇 대 봇 수천 판으로 측정)
- 캐릭터: 가격 대비 승률 45~55%, 선택률이 한 캐릭터에 쏠리지 않을 것
- 시너지별 승률이 비슷할 것(어느 기물 구성이 항상 이기지 않을 것)
- 선후 공격 차이 없음(판이 대칭), 평균 라운드 수 6~8, 돌발 사망으로 끝나는 전투 15% 이하
- (2차) 라운드당 재료 획득 2~3개, 경제 무기만 노리는 전략이 압도하지 않을 것

## 11. 만드는 순서
1. **체스판 전투 시뮬레이션** + 봇 대 봇 + 밸런스 측정 도구 (서버, 화면 없음) — 캐릭터 20명, 기물 시너지, 폰 승급
2. **상점·경제·라운드 진행** (서버) + 봇을 상대로 한 판 완주, 방/로그인/랭킹/항복 연결
3. **iPad 화면**: 판, 대기석, 상점, 전투 관람, 결과 (로비·랭킹·가이드는 재사용)
4. 튜토리얼(첫 판 안내), 연출, 가이드 새로 쓰기
5. (2차) 자원 시스템 얹기

## 12. 기술 메모
- 서버(Cloudflare Durable Object), 방, 로그인(GL Account), 랭킹(D1), 봇(ADMN 테스트 대전), SideStore 배포는 그대로 쓴다.
- 새 시뮬레이션은 `server/src/chess/`(가칭)에 둔다. 옛 `battle/` 코드는 삭제하지 않고 옛 모드로 남긴다.
- 프로토콜에 새 단계(`prep`, `combat`)와 메시지(상점 구매·판매·새로고침, 기물 배치)를 추가한다.
- Unity 클라이언트는 옛 모드 용도로 남기고 새 게임은 iPad 앱만 만든다.

## 13. 1단계 구현 결과 (서버, 화면 없음)
코드: `server/src/chess/` (`roster`, `board`, `sim`, `abilities`, `synergy`, `balance`), 테스트 `server/test/chess.test.ts`, 측정 `npm run balance`.
- 20명 능력 전부 구현(에너지 자동 발동 또는 패시브), 기물 시너지, 폰 승급, 돌발 사망, 결정적 시뮬레이션.
- 공격력 보정(`ATK_SCALE` 2.5)과 기물·캐릭터별 보정을 측정으로 정했다. 같은 팀을 자리 바꿔 싸우는 4000판 기준:

| 지표 | 목표 | 현재 |
|---|---|---|
| 캐릭터 승률 | 45~55% | 44~53% (가장 약한 쪽 마샬 베르그 44%) |
| 시너지(2명) 승률 | 45~55% | 47~51% |
| seat 쏠림 | 48~52% | 50.2% |
| 돌발 사망까지 간 판 | 15% 이하 | 16.8% |
| 무승부 | - | 4.2% |
| 평균 길이 | 6~8라운드 한 판 | 전투 약 15박자 |

- 남은 약점: 3명 시너지(비숍 3명 41%, 나이트 3명 44%)와 퀸 3명(40%)이 약하다(표본이 적다, 100판 안팎). 이 수치는 "예산 14골드로 무작위 팀"이라는 측정 조건의 영향이 커서, 상점과 라운드가 붙은 뒤(2단계) 실제 봇 대전에서 다시 본다.

## 14. 2~4단계 구현 결과
- **2단계 (서버)**: 상점·골드·이자·공용 풀·★2 합성(`chess/game.ts`), 라운드 루프와 봇(`room-state.ts`, `bot.ts`), 항복·기권패, 전적 연동. 테스트 `chess-game.test.ts`, `room-chess.test.ts`.
- **3단계 (iPad)**: 준비 화면(판, 대기석, 상점), 전투 재생(서버 기록 프레임 보간), 결과, `GET /api/chess`. 기물 아이콘은 Xhess 단색 PNG(템플릿 이미지).
- **4단계**: 가이드를 체스 규칙으로 새로 씀(흐름, 상점과 배치, 전투 규칙, 캐릭터, 시너지, 조작), 첫 판 안내 카드, 빈 판으로 준비 끝 확인, 쓰러지는 기물 페이드.
- 남은 것: 기기 확인 후 화면 다듬기, 자원 시스템(9장, 2차 버전).

## 15. 웹 클라이언트
- `web/`: 빌드 없는 순수 JS. 서버가 같은 주소에서 내보내고(`wrangler.jsonc`의 `assets`), iPad 앱과 같은 서버·프로토콜을 쓴다. 웹과 iPad가 서로 대전할 수 있다.
- 준비(판·대기석·상점·자원 패널·드래그/자동 배치·첫 판 안내), 전투 재생, 결과, 가이드, 랭킹 모두 iPad와 같은 기능.

## 16. 매칭, 연출, 봇 난이도 (다음 단계)
- **빠른 대전**: `POST /api/match/join` → `GET /api/match/poll?ticket=` → 방 코드. 레이팅 차이 100 + 기다린 초 × 40 이내로 짝짓고, 서버가 방을 만든다(Durable Object `Matchmaker`, 순수 로직은 `matchmaking.ts`). 웹에만 UI가 있고 iPad는 아직 없다.
- **웹 전투 연출**: 피해·회복 숫자, 능력 링, 쓰러짐 페이드, 승급·채굴 표시, 돌발 사망 표시, WebAudio 합성 효과음(음소거는 기억).
- **봇 난이도** (`?level=easy|normal|hard`, 연습 대전 기본 쉬움, 전체 대전 기본 보통). 측정: `npx tsx scripts/bot-balance.ts`.
  - 쉬운 봇: 무작위로 5개까지 구매, 자원·무기 안 씀. 보통 봇에게 입문 10%, 전체 14% 승리.
  - 어려운 봇: 합칠 캐릭터·시너지를 보고 구매, 남는 골드로 새로고침, 자원 칸 위에 기물 배치, 라운드마다 골드 +1(자원 판 +2). 보통 봇에게 입문 약 79%, 전체 약 73% 승리.
  - 자리 유불리: 공용 풀에서 먼저 뽑는 쪽이 유리해서 라운드마다 상점 채우는 순서를 번갈아 바꿨다. 봇끼리 seat0 승률 약 48~54%.
- **다시 보기**: 서버가 라운드마다 전투 기록(`ChessGame.history`)을 쌓고, 랭킹에 기록되는 판(둘 다 GL 로그인)이 끝나면 D1 `replays` 테이블에 저장한다(`0002_replays.sql`). `GET /api/replays/:id`로 불러온다(id는 내 전적의 `id`). 웹: 준비 화면의 "지난 전투", 결과 화면의 "전투 다시 보기", 랭킹의 전적별 "다시 보기". 일시정지·속도(0.5~4×)·되감기·라운드 선택. 이 기능이 생기기 전의 판은 기록이 없다.
- **관전**: `/ws/:code?spectate=1`로 들어온다(방당 8명, 연습·전체 대전 방은 불가). 관전자는 전투와 체력만 보고(준비 단계의 상점·배치는 안 보인다) 아무것도 조작할 수 없다. 웹: 로비의 "관전" 코드 입력, 방의 "관전 링크 복사"(`/?watch=CODE`).

## 17. 게스트 방 (발표회용)
- **게스트 방**: GL 계정으로 로그인한 사람이 만든다(`POST /api/rooms?guest=1`). 참가자는 GL 계정 없이 **학번(숫자 4~10자리)과 이름**만으로 들어온다(`/ws/:code?guest=학번&name=이름`). 같은 학번이 다시 들어오면 원래 자리로 돌아온다. 게스트는 게스트 방에만 들어갈 수 있고(일반 방은 `unauthorized`), **전적과 레이팅, 다시 보기에는 남지 않는다.**
- **관전**: 방 코드 없이 `GET /api/live`(GL 로그인 필요)로 진행 중인 게스트 방 목록(참가자 학번·이름, 단계, 라운드, 체력)을 보고 고른다. 관전은 GL 로그인이 필요하고 게스트는 관전할 수 없다. 방이 단계·라운드·참가자가 바뀔 때만 `LiveRegistry`(Durable Object)에 알린다. 20분 동안 갱신이 없으면 목록에서 사라진다.
- 웹과 iPad 모두: 로비의 "게스트로 참가", "게스트 방 만들기"(로그인 시), "진행 중인 경기 관전"(로그인 시).
- 발표 구성 예: 컴퓨터(웹, GL 로그인)에서 게스트 방을 만들어 프로젝터에 관전 화면을 띄우고, 아이패드 두 대는 게스트로 참가한다.
- **방 닫기(지우기)**: 방을 만든 GL 계정만 닫을 수 있다(`POST /api/rooms/:code/close`). 방 안의 모든 연결에 `room_closed`를 보내 끊고, 방의 저장 내용(알람 포함)을 지우고 관전 목록에서 뺀다. `GET /api/my-rooms`로 내가 만든 방(게스트·일반)을 보고, 웹·iPad의 "내 방 관리"에서 하나씩 지우거나 모두 닫는다. 방 안에서는 방장에게 "방 닫기" 버튼이 있다. 만든 사람 정보가 없는 옛 방은 앉아 있던 GL 계정이나 닉네임이 같은 사람이 닫을 수 있다. 사람이 모두 나간 방은 10분 뒤 저절로 지워진다(기존 규칙).
- 없는 방(닫힌 방 포함)에 웹으로 들어가려 하면 접속 전에 방 존재를 확인해 바로 알려 준다.

## 18. 준비 화면 개선 (진행 링, 시너지, 아이템 드래그, 사운드·애니메이션)
- **진행 링**: 판에 올린 기물 수 / 올릴 수 있는 수를 둥근 막대로, 가운데에 코인(골드). 가득 차면 초록으로 빛난다. 옆에 시너지 칩(켜진 것은 밝게, 모으는 중은 `1/2`처럼 진행도, 최대 단계는 빛남).
- **아이템 드래그**: 재료 → 재련대(재련), 무기 → 기물 위(장착, 이미 낀 무기가 있으면 서로 바뀜), 무기 낀 기물 → 무기 보관함(해제). 기존의 누르기 방식도 그대로.
- **애니메이션**: 새 기물이 튀어나오고 ★2는 금색으로 반짝, 무기를 끼면 번쩍(웹)·통통 튐(iPad), 상점이 통째로 새로 채워지면 카드가 차례로 날아옴, 골드 숫자가 튐, 단계 전환 페이드. 전투는 피해·회복 숫자, 능력 고리, 공격 돌진, 쓰러질 때 줄어들며 사라짐, 재료 채굴 표시.
- **사운드**: 파일 없이 합성한 효과음(구매·판매·배치·장착·재련·합성·판 가득 참·라운드 시작·전투 시작·타격·능력·쓰러짐·승급·채굴·카운트다운 똑딱·결과)과 선택 가능한 배경 음악(기본 꺼짐). 웹 `js/sfx.js`, iPad `Sfx.swift`가 같은 소리를 낸다. 음소거와 음악 설정은 기억한다.

## 19. 조합 (재료·무기를 합쳐 새 재료·무기 만들기)
- **무기 + 무기**: 같은 무기 둘 → **★2 무기**(효과 1.5배). 다른 무기 둘 → **융합 무기**(두 효과를 각각 75%). ★2·융합은 더 합치지 않는다.
- **무기 + 원재료**: 그 무기의 재료를 합치면 ★2 무기(재련 없이 바로).
- **재료 + 재료**: 같은 희귀도의 서로 다른 재료 둘 → 한 단계 위 희귀도의 재료(흔함→보통→희귀→전설, 전설끼리는 불가). 흔함 6쌍 + 보통 6쌍 + 희귀 3쌍 = 15가지 조합표(`MATERIAL_FUSIONS`, 모든 상위 재료가 한 번 이상 나온다).
- 합치면 둘이 사라지고 결과가 바로 보관함에 들어온다(재련처럼 기다리지 않는다). 준비 단계에서만, 자원 시스템이 있는 판에서만.
- 무기 이름표는 문자열 하나: `a`(기본), `a*`(★2), `a+b`(융합, 사전순). 전투는 낀 기본 무기마다 효과를 내고 확률·수치에 효과 배율을 곱한다(`weaponParts`, `weaponPower`).
- 메시지 `combine`(`{a:{kind,id}, b:{kind,id}}`), 오류 `invalid_recipe`. `GET /api/chess`에 `fusions`(재료 조합표)와 `crafting`(배율)이 있다.
- 측정(`scripts/weapon-balance.ts … star|hybrid`): ★2는 같은 기본 무기보다 +1~9%p, 융합은 ★2와 비슷한 수준.
- 봇: 보통은 같은 무기 둘을 ★2로 합치고, 어려운 봇은 남는 재료를 합쳐 상위 재료로 만들어 재련하고 무기가 기물보다 많으면 융합한다.
- 웹: 아이템을 다른 아이템 위로 끌면 합쳐지고(끄는 동안 결과 미리보기), "⚗ 조합" 버튼을 켜면 둘을 차례로 눌러도 된다. "조합 도감" 탭에 규칙과 조합표가 있다.
